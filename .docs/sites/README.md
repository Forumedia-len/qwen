# Спецификации сайтов кортов

## Обзор

Папка `sites/` содержит спецификации и описания изменений для отдельных сайтов спортивных кортов, использующих систему Active Court. Каждый сайт имеет свою папку с детальным описанием кастомизаций и особенностей.

## Структура спецификаций

### Правила именования папок сайтов

- **Формат**: `{домен-сайта}` (без протокола и расширений)
- **Регистр**: нижний регистр
- **Разделители**: дефисы (-) вместо точек
- **Примеры**:
  - `tennishalle-offenburg` (для tennishalle-offenburg.de)
  - `tennis-club-munich` (для tennis-club-munich.com)
  - `sports-center-berlin` (для sports-center-berlin.de)

### Структура папки сайта

```
sites/{site-domain}/
├── README.md                    # Обзор сайта и основные особенности
├── specification.md             # Детальная спецификация
├── customizations.md            # Описание кастомизаций
├── changes.md                   # История изменений
├── requirements.md              # Требования и задачи
└── assets/                      # Дополнительные файлы (схемы, скриншоты)
```

### Структура спецификации

Каждая спецификация должна содержать:

1. **Общая информация** - домен, тип, дата создания, версия
2. **Локальные изменения** - кастомизации и модификации
3. **Технические детали** - модули, компоненты, статус
4. **Необходимые действия** - задачи и требования
5. **История изменений** - хронология обновлений

## Создание новой спецификации

При создании спецификации для нового сайта следуйте шаблону:

```markdown
# Спецификация сайта {site-name}

## Общая информация

- **Домен**: {domain}
- **Тип**: {type}
- **Дата создания спецификации**: [дата]
- **Версия**: 1.0

## Локальные изменения и кастомизации

### 1. [Название изменения]

**Описание**: [Подробное описание изменения]

**Технические детали**:

- Модуль: [название модуля]
- Компонент: [название компонента]
- Статус: [статус реализации]

**Необходимые действия**:

- [ ] [Описание задачи 1]
- [ ] [Описание задачи 2]
- [ ] [Описание задачи 3]

## История изменений

### Версия 1.0 (дата)

- [Описание изменений]
- [Описание изменений]
```

## Правила работы со спецификациями

1. **Создавать папку** для каждого нового сайта
2. **Использовать единый формат** для всех спецификаций
3. **Документировать все изменения** и кастомизации
4. **Обновлять статус задач** по мере выполнения
5. **Вести историю изменений** с версиями
