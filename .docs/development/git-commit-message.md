Сформируй информативное сообщение git-коммита на русском языке по текущим изменениям в проекте.

Требования:

- Сообщение коммита должно быть на русском языке.
- Используй стиль Conventional Commits.
- Тип коммита оставляй на английском:
  - feat, fix, refactor, test, docs, chore, perf, build, ci
- Scope указывай на английском или в формате имени модуля, если он очевиден.
- Краткое описание после двоеточия пиши на русском.
- Subject должен быть коротким и конкретным, обычно до 50-72 символов.
- Коммит должен описывать одно логическое изменение.
- Описание должно отвечать на вопрос:
  - что изменится после применения этого коммита?
- Форматируй ответ как обычный текст с настоящими символами перевода строки.
- Не используй табуляцию или пробелы перед пунктами body: каждый маркер `- ` должен начинаться с первого символа новой строки.
- Не возвращай сообщение одной строкой, если у коммита есть body, footer или `BREAKING CHANGE`.
- Не перечисляй файлы вместо смысла.
- Не пиши общие фразы:
  - "обновлены файлы"
  - "исправлены баги"
  - "изменения"
  - "правки"
  - "доработки"
  - "мелкие исправления"
  - "update"
  - "fixes"
  - "changes"
- Указывай, что именно изменилось и зачем.
- Если изменений больше одного или они требуют пояснения, добавь body на русском языке.
- Body должен объяснять важные изменения в поведении, структуре, БД, API или конфигурации.
- Группируй связанные изменения в 2-5 коротких пунктов.
- Явно упоминай важные последствия:
  - изменения схемы БД;
  - миграции;
  - breaking changes;
  - изменения API;
  - изменения пользовательского поведения;
  - конфиги и env-переменные.
- Если есть breaking changes, добавь секцию `BREAKING CHANGE` с описанием на русском.
- Если коммит связан с issue/task, добавь ссылку в footer.
- Коммит должен быть понятен через полгода.

Требования к переносам строк:

- После subject обязательно добавь пустую строку перед body.
- Каждый пункт body размещай на отдельной физической строке.
- Не объединяй соседние пункты body в одну строку.
- Между пунктами body не добавляй пустые строки.
- Перед footer или `BREAKING CHANGE` обязательно добавь одну пустую строку.
- Используй настоящие переносы строк, а не текстовые последовательности `\n` и не HTML-тег `<br>`.
- Запрещено склеивать части сообщения, например: `описание- Следующий пункт` или `последний пунктBREAKING CHANGE`.
- Если есть body, итоговый текст обязательно должен содержать последовательность `subject`, пустая строка, пункты body.
- Перед возвратом ответа проверь:
  - каждый маркер `- ` находится в начале отдельной строки;
  - перед первым пунктом body есть пустая строка;
  - `BREAKING CHANGE:` находится на отдельной строке и отделён от body пустой строкой.

Перед созданием сообщения:

1. Посмотри `git diff --staged`.
2. Определи главную цель изменений.
3. Отдели важное поведение от второстепенных технических деталей.
4. Сформулируй сообщение так, чтобы было понятно:
   - что изменилось;
   - зачем это изменилось;
   - какое поведение появилось или изменилось.

Хорошие примеры:

```text
feat(lockers): добавить установку модуля локеров
fix(auth): исправить проверку истечения токена
refactor(order): упростить расчет итоговой суммы
fix(lockers): не создавать повторно состояние locker
feat(lockers): добавить SQL-шаблоны установки
feat(lockers): добавить проверку установки таблиц локеров
```

Плохие примеры:

```text
feat(lockers): добавить локеры, поправить стили и обновить конфиг
fix(lockers): исправлен баг
feat(lockers): изменить LockerInstallEngine.php
chore: update
fix: fixes
chore: changes
```

Формат ответа:

```text
<type>(<scope>): <краткое описание на русском>

- <важное изменение>
- <важное изменение>
- <важное изменение>

<footer if needed>
```

Пример хорошего коммита:

```text
feat(lockers): добавить установку модуля локеров

- Создать обязательные таблицы локеров из SQL-шаблонов
- Добавить привязку locker_cell_id к webio_outputs
- Зарегистрировать состояние locker для webio
```

Верни только сырой текст сообщения коммита без Markdown-блока, кавычек и дополнительных пояснений. Не удаляй и не заменяй обязательные переносы строк.
