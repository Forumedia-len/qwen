# Widget

## Назначение и текущий этап

`widget` — публичный интерфейс для встраивания в iframe другого сайта. Он использует существующие
правила бронирования, авторизацию игроков, личный кабинет и платежные модули `site`.
После проверки рабочей копии оболочка оформлена по Figma Dellbrück: компактная навигация,
выбор даты и раскрывающийся календарь. Шапка, подвал и боковая колонка сайта в оболочку не входят.
Правила бронирования, формы и набор разделов продолжают наследоваться от сайта.

Локальный адрес: `https://tennisbuchung-test.loc/widget/`.
Пример встраивания: `https://tests.loc/widget-test.html`.
Виджет подключается к БД из настроек этой установки; отдельная база или новые таблицы для него не нужны.

## Включение и отключение

Константа `USE_WIDGET` объявлена в `app/uses/defined.php`; по умолчанию `false`.
Для включения интерфейса установите в `app/uses/defined.php` или `app/uses/defined.loc.php` конкретной площадки:

```php
defined('USE_WIDGET') || define('USE_WIDGET', true);
```

`App::checkDeviceAvailability()` возвращает HTTP 404 для `/widget/` и вложенных адресов до обработки
статических файлов, запуска сессии и действий страницы. POST-запросы также отклоняются без выполнения действия.
Для браузера используется стандартная страница 404, для AJAX и запросов без `Accept: text/html` — простой текст.
Остальные устройства, включая основной сайт, не зависят от этой константы.

## Маршруты и наследование

- `Url` распознаёт префикс `/widget/`, шаблон `widget` и суффикс контроллеров `Widget`.
- `WidgetDeviceAction` наследует подготовку и завершение страницы от `SiteDeviceAction`.
- Явные точки входа в `widget/*.php` вызывают соответствующие обработчики сайта через автозагрузчик.
  `widget/index.php` использует обработчик `reservations.php`; новости доступны через `aktuelles.php`.
- Для контроллеров приоритет: каталог `controllers/widget`, класс с суффиксом `Widget`,
  каталог `controllers/site`, общий контроллер. Модели и бизнес-правила остаются общими.
- Представления, partials и layouts сначала ищутся для `widget`, затем для `site`, затем по существующим
  общим путям. Локальные переопределения установки продолжают участвовать в поиске.
- Структура загружается в порядке `site → widget`; в пределах каждого устройства сохраняется штатный
  порядок общих и локальных файлов. `app/structure/structure.widget.php` содержит только отличия;
  пункт внешнего сайта `homepage` исключён из меню виджета через `menu => false`.
- Переводы загружаются в порядке `common → site → widget`. Это относится и к переводам структуры.
  При добавлении собственных фраз используются английские ключи и значения для de, en, ru.

Порядками поиска и объединения управляет `Service::templates()` (`TemplateResolver`).
`Url::getTemplateHierarchy()` остаётся совместимой обёрткой. Тот же поиск используется для оболочки
HTTP-ошибки; если шаблон widget отсутствует, применяется соответствующий шаблон site.

Ссылки и действия форм интерфейса строятся через `site_url()` с сохранением `/widget/`.
Общие API используют `base_url()`, ресурсы шаблона виджета — `cdn_url()`.
Старые относительные ссылки содержимого на `assets/` и `uploads/` обслуживаются из корня установки:
`/widget/assets/common/...` обращается к тому же файлу, что `/assets/common/...`.

## Шаблоны и ресурсы

`app/tpl/widget/default.php` задаёт оболочку, `_navigation.php` строит меню из штатной структуры
и сохраняет ограничения пунктов личного кабинета. `_style.php` и `_script.php` подключают ресурсы устройства.
В `<head>` оболочки постоянно выводится `<meta name="robots" content="noindex, indexifembedded">`,
независимо от `NOINDEX_SITE`. Резервная HTML-страница ошибки виджета использует те же директивы.
Общий переключатель остальных устройств описан в [конфигурации](../core/configuration-system.md#индексация-html-страниц).
Нижняя ссылка «Impressum / Datenschutz» в оболочке виджета не выводится; страница `user_info.php` доступна по прямому адресу.
После входа имя пользователя видно в блоке авторизации, а баланс, личный кабинет, бронирования
и выход — в постоянной строке под навигацией. Выпадающего меню для этих ссылок нет.
Ссылки продолжают учитывать `show_client_data`, `HIDE_LINK_AUTH_USER`, типы площадок и доступ пользователя.
Личный кабинет открывает существующую страницу `registration.php?action=view`; баланс берётся
из `current_client_data['prepayment_sum']`. Текст и иконка входа подбираются по контрасту с фоном кнопки.
Кнопка входа и блок имени используют исходную иконку сайта `common/images/icon/user.svg`:
копия без XML-декларации хранится в `app/tpl/widget/images/user.svg` и подключается через PHP include.
Основное меню и кнопка входа используют uppercase; на мобильных экранах это относится и к ссылкам личного кабинета.
На ширинах 768–991 px меню перестраивается в две строки: площадки с авторизацией, затем остальные разделы.
`core/modules/reservations/views/widget/_calendar.php` использует те же данные, месяцы, ограничения
и переводы, что календарь сайта. Заголовок рядом с датой берётся из
`AreasEngine::getTitleByTypeAndSport(..., 'title_full')`: выбранные тип площадки и вид спорта
с переводами общего справочника. Он обновляется при переключении типа или спорта и не содержит дату.
Панель открывается под датой на desktop и мобильных экранах,
закрывается повторным нажатием на дату, по Escape, клику снаружи и выбору дня. При смене месяца остаётся открытой
через параметр `calendar=1`. Существующий cookie `calendarVisibility` больше не управляет этой панелью.
Выбор даты и календарь выводятся только вместе с дневным или недельным расписанием.
`ReservationView::showCalendar` по умолчанию выключен и включается в `showReservations()`;
оболочка widget проверяет этот признак. На оформлении и остальных действиях бронирования календаря нет.
Вкладки Tagesansicht/Wochenansicht центрируют текст относительно иконок. Строки `.period` используют flex:
время, чекбокс, индикаторы и действия выровнены по вертикали, без прежних смещений под старый шрифт.

Геометрия календаря сверена с растровым изображением `1:54` внутри группы `1:57` в Figma:
панель шириной 289 px, белый внутренний блок 226 px и ячейки 32 px. Календарь начинается
с названия месяца и дней недели; дополнительного блока с сегодняшней датой нет.
Высота определяется числом недель и переводами легенды. Серая внешняя подложка сохранена по макету.
На всех страницах общий блок `main` имеет белый фон и тонкую рамку `#b4b7c7`, включая заголовок и содержимое.
Максимальная ширина контейнера `.fm-widget-shell` — 1920 px; на широком экране он центрируется.
Вокруг рамки виден фон оболочки `#f9f9f9` из Figma (`1:7`). На мобильных экранах рамка сохраняется,
уменьшаются только отступы; внешние скругления и тень оболочки убираются.

Стрелки экспортированы через Figma Desktop Bridge из узлов `1:25`, `1:29`, `1:50` и хранятся
в `app/tpl/widget/images/` для серверного `include` SVG; отдельных HTTP-запросов к ним нет.

Каталоги сохраняют структуру исходного сайта, но общие ресурсы виджета поставляются только с CDN:

| Ресурс | Размещение |
|---|---|
| Основной CSS, дополнения и JS устройства | CDN `active-court/main/assets/widget/` |
| Исходники Sass | CDN `active-court/main/assets/sass/widget/` |
| Изображения устройства | CDN `active-court/main/assets/widget/images/` |
| Общие библиотеки, шрифты и изображения | CDN `active-court/main/assets/common/`, `assets/third/` |
| Логотипы площадки | Локальные `assets/common/images/logo.png`, `logo_sm.png` |
| Необязательные дополнения площадки | Локальные `assets/widget/css/custom.css`, `assets/widget/js/custom.js` |

В CDN `assets/gulp/` доступны `gulp widgetSass` и `gulp widgetWatch`.
Первая команда выпускает CSS, `.min.css` и sourcemap по той же схеме, что `desktopSass`.
Общий watcher также наблюдает за `sass/widget`. Исходники `site` продолжают собираться своими задачами.

Общие правила нового оформления находятся в CDN `assets/sass/widget/interface.scss`.
Собранный `widget/css/interface.min.css` подключается после CDN `default.min.css` и модульных стилей.
Шаблоны widget передают `assetOrigin => cdn` в общие `_style.php`/`_script.php`: это переводит на CDN
также tooltip и другие модульные подключения с прежним источником `base`/`site`.
Без этого параметра поведение остальных устройств сохраняется.
Форма подтверждения cookies в widget не выводится, включая страницы HTTP-ошибок.
`WidgetDeviceAction` отключает подключение её CSS и JS через `showCookieConsent`;
обычный сайт сохраняет прежнее поведение. Скрытие формы не записывает согласие пользователя.
URL по дескрипторам ресурсов готовит `AssetHelper::cssUrl()`/`jsUrl()`, HTML-теги остаются в шаблонах.
Сохраняются прежние различия: CSS принимает truthy-флаг отключения `css/`, JS — только `true`;
источник `site` поддерживается для JS, а у CSS соответствует `base`.
Локальные `custom.css` и `custom.js` подключаются последними в своих группах только при наличии файла
в корне установки (`ROOT_PATH`). Проверку и версию по времени изменения выполняет `AssetHelper::localCustomUrl()`.
Пустые файлы создавать не требуется.
Старый локальный `assets/widget/css/default.min.css` больше не подключается; его локальная сборка не нужна для виджета.
URL логотипов передаются оболочкой в `--ac-image-logo` и `--ac-image-logo-sm`, поэтому CDN CSS
использует логотип текущей площадки. В шапке окна входа `background-size: contain` вписывает логотип целиком с сохранением пропорций.
Загруженные через админку баннеры остаются локальными как содержимое сайта;
общая заглушка `common/images/bilder/no.gif` загружается с CDN.
В `_style.php` версия поставки `$widgetStyleVersion` добавляется к URL CDN `default.min.css`
и `interface.min.css`. При следующем изменении этих стилей версию нужно обновить вместе со сборкой,
чтобы браузер запрашивал новую копию CSS.

## Типографика

Шрифты Google Fonts загружаются с CDN проекта из существующего каталога `assets/common/fonts/`:
`Oswald/`, `Barlow/`, `BarlowCondensed/`. WOFF2 и лицензии `OFL.txt` находятся рядом.
Подключение и переопределение типографики выполняются в CDN через `sass/widget/common/_typography-fonts.scss`
и `_typography.scss`, включённые в `interface.scss` и существующую сборку `widgetSass`.

| Роль | Шрифт | Размер / жирность |
|---|---|---|
| Главный заголовок, визуальный H1 | Oswald | 52 px / 700 |
| Заголовок раздела, H2 | Oswald | 38 px / 700 |
| Подзаголовок, H3 | Oswald | 26 px / 700 |
| Основной текст | Barlow | 17 px / 400 |
| Кнопки, основная навигация, вкладки | Barlow Condensed | 17 px / 700 |

Для H1 и H2 согласовано начертание Oswald 700: в оригинальном шрифте нет 800.
Главный заголовок `.fm-booking-title` / `.fm-page-title` сохраняет HTML `h2`, но получает визуальный уровень H1.
До 767 px включительно заголовки уменьшаются: H1 — 32 px, H2 — 28 px, H3 — 22 px.
Основной текст остаётся 17 px; длинные заголовки переносятся.
Календарные подписи и компактные служебные метки сохраняют свою геометрию.
Для собственных меток предусмотрен `.fm-tag` с Barlow Condensed 600.
Oswald включает кириллицу; для отсутствующих в Barlow символов используется существующий Roboto, затем системный sans-serif.

## Цвета темы

Цвета задаются атрибутами iframe: `data-color` — основной и `data-accent` — дополнительный.
Маркер `data-ac-widget` включает доставку темы. Скрипт `embed.js` подключается один раз на родительской странице:

```html
<iframe src="https://tennisbuchung-test.loc/widget/" data-ac-widget
        data-color="#00471f" data-accent="#ffb900"
        title="Active Court Buchung" style="width:100%;height:100vh;border:0"></iframe>
<script src="https://cdn/active-court/main/assets/widget/js/embed.js?v=20260917-1" defer></script>
```

В примере указаны локальные адреса; при публикации используются адрес установки и её CDN.
Поддерживаются `RRGGBB`, `RGB` и те же значения с `#`; в атрибутах `#` не нужно кодировать.
Регистр не важен. Базовая палитра задаётся константами в `app/uses/defined.php` площадки:

```php
defined('WIDGET_PRIMARY_COLOR') || define('WIDGET_PRIMARY_COLOR', '00471f');
defined('WIDGET_ACCENT_COLOR') || define('WIDGET_ACCENT_COLOR', 'ffb900');
```

Эти цвета применяются при прямом открытии `/widget/` и до получения настроек iframe.
Корректные `data-color` и `data-accent` имеют приоритет над соответствующими константами.
Отсутствующий или некорректный атрибут заменяется цветом из константы независимо от второго атрибута;
произвольный CSS не принимается. Атрибуты можно менять после загрузки, новые iframe подключаются автоматически.

Доставка использует `postMessage`: родитель проверяет origin по `src` и окно отправителя, виджет принимает
тему только от непосредственного родителя и закрепляет его origin. Сигнал `activecourt:ready` не содержит
данных пользователя. При загрузке, переходах внутри iframe и возврате из кеша страниц тема отправляется снова.
Цвета применяются к пяти разрешённым CSS-переменным через `theme.js`; URL и серверная сессия не изменяются.
Несколько iframe могут иметь независимые темы. Без `embed.js` атрибуты другого origin недоступны виджету.

GET-параметры `color`/`accent` и прежние значения цветов в сессии игнорируются.
Некорректная константа заменяется безопасным цветом из макета: `00471f` для основного и `ffb900` для акцентного.
Удаление атрибута iframe возвращает соответствующий цвет к значению константы.

CSS-контракт: `--ac-color-primary`, `--ac-color-on-primary`, `--ac-color-accent`, `--ac-color-on-accent`, `--ac-color-selected`.
`ColorsHelper` отвечает за строгую нормализацию HEX, относительную яркость sRGB и отношение контраста.
`TemplateThemeHelper` хранит значения по умолчанию и правила темы, не обращаясь к запросу или сессии;
`getCssVariables()` возвращает готовые имена и значения CSS-переменных. `WidgetDeviceAction` проверяет
запрос и разрешает встраивание, не читая и не сохраняя цвета. Его прежние `normalizeColor()` и `getThemeColors()`
сохранены как обёртки; шаблон передаёт константы в хелпер темы для начальной палитры.
`TemplateThemeHelper::getClientConfig($color, $accent)` принимает необязательные базовые цвета,
нормализует их и передаёт в JSON вместе с порогами контраста. Хелпер не зависит от констант конкретного устройства.
Браузерный `theme-helper.js` выполняет проверку HEX и расчёты отдельно от обмена сообщениями;
совпадение результата с PHP проверяется на одном наборе входных значений.
`TemplateThemeHelper::getColors()` выбирает текст по относительной яркости sRGB: начиная с 0.6 — чёрный,
ниже — белый. По согласованному оформлению красный `ff0000` и жёлтый `ffb900` используют белый текст;
очень светлые и пастельные фоны — чёрный. Иконка пользователя наследует тот же цвет.
Основной цвет применяется к навигации, активной вкладке корта, отметке сегодняшней даты и кнопкам бронирования/форм.
Дополнительный цвет применяется к кнопке входа, блоку имени и выбранному дню календаря.
Активный пункт меню выделяется дополнительным цветом текста, как цвет фона кнопки входа, без подчёркивания или рамки.
Для близких цветов (отношение яркостей с поправкой 0.05 ниже 2:1) используется чёрный/белый текст основного фона.
Заголовки таблиц расписания имеют белый фон и чёрный текст, как в макете, независимо от базового цвета.
Смысловые цвета занятых, заблокированных и собственных бронирований сохраняются.
Наведение и фокус не добавляют рамки, тени и подсветку меню, кнопок, календаря или строк расписания.
Обычные границы полей/контейнеров и постоянное выделение активного раздела сохраняются.
Полоса и интерактивные акценты окна входа также используют базовый цвет. Фон блока регистрации
`--ac-color-primary-soft` смешивает 12% базового цвета с белым, а текст `--ac-color-primary-ink` —
45% базового цвета с чёрным. Изображение логотипа площадки не перекрашивается.

## Сессия и iframe

Имя сессии: `SESSION_COURT . '_widget'`; вход на основном сайте и вход в виджете независимы.
Cookie сессии виджета имеет `Secure`, `HttpOnly`, `SameSite=None`. Cookie согласия
также поддерживают cross-site iframe. Для остальных устройств сохраняется `SameSite=Lax`.
Требуется HTTPS на стороне виджета и разрешение браузера на использование cookies в iframe.
Полная блокировка сторонних cookies настройками браузера может препятствовать авторизации.

Только `WidgetDeviceAction` снимает `X-Frame-Options`. Небезопасные HTTP-методы с чужим `Origin`
или `Sec-Fetch-Site: cross-site` получают 403; формы самого iframe отправляются с origin виджета.
Штатные серверные callbacks платежей остаются общими. Политику `frame-ancestors`, заданную веб-сервером,
при развёртывании следует согласовать с разрешёнными сайтами встраивания.

## Проверки

Регрессионная группа `widget-device` в соседнем репозитории тестов проверяет маршруты устройств,
приоритеты контроллеров и представлений, layouts, переводы и защиту от cross-site POST.
Capability `core.widget-toggle` проверяет оба значения `USE_WIDGET`: отключение всех маршрутов виджета
до обработки файлов и действий, включая POST, и независимость остальных устройств.
Также проверяются CDN для модульных ресурсов, прежние источники ресурсов сайта и подключение
существующих локальных custom-файлов последними; отсутствующие файлы не попадают в HTML.
Capabilities `core.widget-device` и `core.widget-theme` включены в текущем worktree.
`WidgetThemeTest` проверяет HEX, короткую запись, неподходящие типы и попытки CSS-инъекции,
независимые значения по умолчанию, контраст обоих фонов и активного пункта меню, включая одинаковые цвета.
`WidgetEmbedThemeTest` (capability `core.widget-embed-theme`) запускает Node-проверки настоящих скриптов CDN:
совпадение с PHP, изоляцию iframe, проверку отправителя и origin, повторную загрузку и изменение атрибутов.
Путь к соседнему репозиторию CDN можно задать переменной `AC_TEST_CDN_ROOT`.
Capability `core.widget-theme-attributes-only` включает проверки игнорирования цветов из запроса и старой сессии.
Группа `template-responsibilities` отдельно проверяет хелперы цветов, темы и ресурсов, приоритет устройства
перед namespace, объединение структуры, явные пути и устройства, layouts с другим расширением,
родительскую оболочку ошибки и дополнительные пути представлений. Для неё включены capabilities
`core.template-resolver`, `helpers.colors`, `helpers.template-theme` и `helpers.assets`.

Для браузерной приёмки проверяются вход, переходы по страницам, дневной и недельный календарь,
личный кабинет, одна тестовая бронь и её отмена, ширины от 320 px до desktop.
Реальные платежи и отправка писем проверяются только в отдельно согласованном сценарии;
для локального прогона писем существует штатный `SAVE_EMAIL_TO_FILE`.
