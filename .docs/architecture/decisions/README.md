# Архитектурные решения

Раздел хранит Architecture Decision Records (ADR): принятые технические решения, их контекст и последствия.

## Реестр

| ADR | Статус | Решение |
|---|---|---|
| [ADR-001](adr-001-documentation-lifecycle.md) | принято | Жизненный цикл проектной документации |
| [ADR-002](adr-002-cross-platform-cli.md) | принято | Кроссплатформенные CLI-команды проекта |
| [ADR-003](adr-003-courses-availability-sources.md) | принято | Курсы как самостоятельный источник занятости; отдельные технические периоды без обычных броней |
| [ADR-004](adr-004-courses-venue-payments.md) | принято | Площадка принимает оплату курсов при аренде и найме тренера; различаются взаиморасчёты |

## Статусы

- `предложено` - решение обсуждается и ещё не обязательно к применению;
- `принято` - решение действует;
- `заменено` - действует более новый ADR, ссылка на него обязательна;
- `отменено` - решение больше не применяется и не имеет прямой замены.

## Добавление решения

1. Создайте документ из [шаблона](adr-template.md).
2. Назовите файл `adr-NNN-краткое-название.md`.
3. Добавьте ADR в таблицу реестра.
4. Сошлитесь на связанные модули, планы или эксплуатационные инструкции.
5. Не переписывайте принятое решение задним числом: изменение оформляется новым ADR.
