# Обзор архитектуры Active Court

## Введение

Active Court построен на основе модульной архитектуры с использованием паттерна Service Locator и принципов SOLID. Система спроектирована для обеспечения высокой масштабируемости, гибкости и поддерживаемости.

## Архитектурные принципы

### 1. Модульность

- Каждый функционал вынесен в отдельный модуль
- Модули независимы друг от друга
- Возможность отключения/включения модулей
- Четкое разделение ответственности

### 2. Service Locator Pattern

- Централизованный доступ к сервисам
- Dependency Injection через статические методы
- Единая точка входа для всех компонентов
- Упрощение тестирования

### 3. MVC Pattern

- **Model** - работа с данными через движки
- **View** - шаблоны и представления
- **Controller** - обработка запросов и бизнес-логика

### 4. Многослойная архитектура

```
┌─────────────────────────────────────┐
│           Presentation Layer        │
│  (Site, Admin, Touch, Display, API) │
├─────────────────────────────────────┤
│           Application Layer         │
│        (Controllers, Actions)       │
├─────────────────────────────────────┤
│            Domain Layer             │
│         (Modules, Engines)          │
├─────────────────────────────────────┤
│         Infrastructure Layer        │
│    (Database, File System, Cache)   │
└─────────────────────────────────────┘
```

## Ключевые компоненты

### 1. Service Locator (`Service`)

Центральный компонент для доступа ко всем сервисам системы:

```php
// Доступ к основным сервисам
Service::app()           // Главное приложение
Service::engines()       // Движки данных
Service::session()       // Управление сессиями
Service::request()       // Обработка запросов
Service::response()      // Формирование ответов
Service::view()          // Система представлений
Service::lang()          // Локализация
Service::structure()     // Структура данных
```

### 2. Приложение (`App`)

Главный класс приложения, управляющий жизненным циклом:

```php
class App {
    public function run() {
        // 1. Инициализация запроса
        // 2. Определение типа устройства
        // 3. Выполнение действий устройства
        // 4. Загрузка модуля
        // 5. Выполнение контроллера
        // 6. Формирование ответа
    }
}
```

### 3. Модули (`BaseModule`)

Базовый класс для всех модулей системы:

```php
class BaseModule extends Entity {
    protected string $mode = '';
    protected $controller;
    protected $action;
    protected bool $useRouting = false;

    public function exec($action = null, $key = null, $controllerName = null) {
        // Логика выполнения модуля
    }
}
```

### 4. Движки (`Engines`)

Специализированные классы для работы с данными:

```php
class Engines {
    public $accounts;     // Управление аккаунтами
    public $areas;        // Управление зонами
    public $clients;      // Управление клиентами
    public $reservations; // Управление бронированиями
    public $users;        // Управление пользователями
    // ... другие движки
}
```

### 5. Device Actions

Действия для разных типов устройств:

```php
interface DeviceActionInterface {
    public function before();
    public function after($variables);
}
```

## Поток выполнения запроса

```mermaid
graph TD
    A[HTTP Request] --> B[App::run()]
    B --> C[Service::request()]
    C --> D[getDeviceAction()]
    D --> E[DeviceAction::before()]
    E --> F{Static File?}
    F -->|Yes| G[Return File]
    F -->|No| H[Load Module]
    H --> I[Module::exec()]
    I --> J[Controller::action()]
    J --> K[DeviceAction::after()]
    K --> L[HTTP Response]
```

### Детальное описание:

1. **Получение запроса** - `Service::request()` парсит HTTP запрос
2. **Определение устройства** - система определяет тип устройства (site, admin, touch, display, api)
3. **Предварительные действия** - `DeviceAction::before()` выполняет подготовительные операции
4. **Проверка статических файлов** - если запрос к статическому файлу, возвращается напрямую
5. **Загрузка модуля** - на основе URL определяется и загружается соответствующий модуль
6. **Выполнение контроллера** - модуль выполняет нужный контроллер и действие
7. **Постобработка** - `DeviceAction::after()` выполняет финальные операции
8. **Формирование ответа** - результат отправляется клиенту

## Типы устройств

### 1. Site (Веб-сайт)

- Основной интерфейс для пользователей
- Адаптивный дизайн
- Формы бронирования
- Личный кабинет

### 2. Admin (Админ-панель)

- Управление системой
- Настройки и конфигурация
- Отчеты и аналитика
- Управление пользователями

### 3. Touch (Сенсорные экраны)

- Терминалы самообслуживания
- Быстрое бронирование
- Оплата на месте
- Информационные экраны

### 4. Display (Дисплеи)

- Информационные экраны
- Расписание кортов
- Статус занятости
- Рекламные материалы

### 5. API (Программный интерфейс)

- RESTful API
- Интеграция с внешними системами
- Мобильные приложения
- Автоматизация процессов

## Преимущества архитектуры

### 1. Масштабируемость

- Легкое добавление новых модулей
- Независимое развитие компонентов
- Горизонтальное масштабирование

### 2. Гибкость

- Поддержка различных типов устройств
- Настраиваемые интерфейсы
- Модульная конфигурация

### 3. Поддерживаемость

- Четкое разделение ответственности
- Единообразная структура кода
- Документированные интерфейсы

### 4. Тестируемость

- Изолированные компоненты
- Dependency Injection
- Mock-объекты для тестирования

## Заключение

Архитектура Active Court обеспечивает надежную основу для развития системы управления спортивными кортами. Модульная структура и использование современных паттернов проектирования делают систему гибкой, масштабируемой и легко поддерживаемой.
