# Структура проекта Active Court

## Обзор структуры

Проект Active Court имеет четкую модульную структуру, разделенную по функциональности и типам компонентов.

Код приложения разрабатывается в **git worktree** (отдельные рабочие деревья одной кодовой базы — ветки или варианты функционала с небольшими отличиями). Рядом с worktree — отдельный репозиторий unit-тестов:

```
{worktree}/                 # Код приложения (namespace AC\)
tests/                      # Codeception (отдельный git-репозиторий)
    ├── codeception.yml
    ├── _bootstrap.php        # autoload AC\ из worktree (AC_APP_ROOT)
    └── tests/unit/
```

Структура **корня worktree** (каталог с `app/`, `core/`, …):

```
app/                    # Основные компоненты приложения
core/                   # Ядро системы
engines/                # Дополнительные движки
classes/                # Внешние библиотеки
display/                # Интерфейс дисплеев
touchscreen/            # Интерфейс сенсорных экранов
mapi/                   # API интерфейс
uploads/                # Загружаемые файлы
at/                     # Административные инструменты
street/                 # Уличные терминалы
.docs/                  # Документация (в worktree)
```

## Ключевые файлы

### 🚀 Точки входа

- **`index.php`** - Главная точка входа для веб-сайта
- **`bootstrap.php`** - Инициализация системы
- **`config.php`** - Основные конфигурации

### 🔧 Конфигурация

- **`app/config/AppConfig.php`** - Настройки приложения
- **`app/config/DBConfig.php`** - Настройки базы данных
- **`app/config/AuthConfig.php`** - Настройки авторизации

### 📱 Интерфейсы

- **`touchscreen/index.php`** - Сенсорные экраны
- **`display/index.php`** - Дисплеи
- **`mapi/api.php`** - API

### 🧩 Модули

Каждый модуль в `core/modules/` содержит:

- **Модуль** - основной класс модуля
- **Контроллеры** - обработка запросов
- **Модели** - работа с данными
- **Представления** - шаблоны

## Принципы организации

### 1. Разделение по функциональности

- Каждый модуль отвечает за определенную область
- Четкие границы между модулями
- Минимальные зависимости между модулями

### 2. Разделение по типам устройств

- Отдельные интерфейсы для разных устройств
- Специализированные шаблоны
- Адаптивные компоненты

### 3. Конфигурационная гибкость

- Централизованная конфигурация
- Возможность переопределения настроек
- Окружение-зависимые конфигурации

### 4. Масштабируемость

- Легкое добавление новых модулей
- Расширение существующих компонентов
- Поддержка плагинов

## Рекомендации по разработке

### Добавление нового модуля

1. Создать папку в `core/modules/`
2. Наследовать от `BaseModule`
3. Создать контроллеры и модели
4. Добавить шаблоны в `app/tpl/`
5. Настроить маршруты в `app/routes/`

### Добавление нового типа устройства

1. Создать DeviceAction в `app/actions/device/`
2. Добавить шаблоны в `app/tpl/`
3. Настроить маршруты
4. Обновить конфигурацию

### Расширение функциональности

1. Использовать существующие движки
2. Следовать паттерну Service Locator
3. Соблюдать принципы SOLID
4. Документировать изменения

Эта структура обеспечивает четкую организацию кода, упрощает навигацию и поддерживает принципы модульной архитектуры.
