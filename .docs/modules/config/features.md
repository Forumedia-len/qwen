# Дополнительные возможности (модули)

## Назначение

`Дополнительные возможности (модули)` — подпункт модуля `config` для управления функциональными возможностями, которые могут быть нужны не всем сайтам.

Система обслуживает много сайтов с разными сценариями работы, поэтому часть функционала должна включаться точечно для конкретного сайта/клуба. Раздел хранит бизнес-решение администратора: использовать возможность в интерфейсе и пользовательских сценариях или скрыть её.

## Принцип работы

Для каждой возможности хранится отдельный флаг включения. Например:

```text
features.lockers.enabled
```

Флаг означает только, что сайт должен использовать соответствующую возможность. Он не заменяет техническую проверку готовности модуля.

В таблице `config` флаг хранится по scoped-совместимой схеме `type + alias`:

| Type | Alias | Назначение |
| --- | --- | --- |
| `features\|lockers` | `enabled` | Включает бизнес-доступность шкафчиков. |

Подробнее о формировании `type` и `alias`: [scoped-config.md](/.docs/modules/config/scoped-config.md#global-domain-settings).

Административная форма находится в `config.php?mode=features` (`Общие настройки -> Дополнительные возможности`).

Новая возможность добавляется в реестр `ConfigFeaturesModel::features()`. Сервис проверки принимает имя возможности и сам собирает `type`:

```php
ConfigFeatureService::isEnabled('lockers'); // type: features|lockers, alias: enabled
```

После сохранения раздела `features` включенные возможности запускают свою идемпотентную подготовку. Для шкафчиков это `LockerInstallService::ensureInstalled()`: он создает отсутствующие таблицы, добавляет нужные поля/индексы и служебные записи, если они еще не установлены. Проверка установки шкафчиков учитывает не только наличие таблиц, но и обязательные поля, индексы и служебные записи. Если подготовка завершилась ошибкой, флаг возможности откатывается обратно в `0`. Поэтому включение флага администратором означает "подготовить модуль к настройке", а не отдельный ручной шаг установки.

Для модулей, которым нужны собственные таблицы или миграции, итоговая доступность должна проверяться по двум условиям:

```php
$available = $featureEnabled && $moduleInstalled;
```

Например для шкафчиков:

- `featureEnabled` — админ включил возможность `Шкафчики`;
- `moduleInstalled` — таблицы модуля шкафчиков установлены;
- полноценное меню и интеграция в бронированиях доступны только когда оба условия истинны.

## Технические флаги внутри возможностей

Флаг возможности в `config` отвечает за бизнес-решение: нужен ли сайту модуль. Он не обязан включать все экспериментальные или будущие режимы внутри этого модуля.

Например для шкафчиков базовый модуль может быть включен, но временные цены ячеек остаются отключенными техническим флагом:

```php
USE_LOCKER_CELL_TIME_PRICES
```

Пока этот флаг не задан или равен `false`:

- форма дополнительных цен ячеек в админке не показывается;
- сохранение ячейки не перезаписывает правила из `locker_cell_prices`;
- расчет стоимости использует базовое поле `locker_cells.price`.

Такой флаг нужен для подготовленного, но еще не включенного функционала: структура хранения уже есть, но пользовательский интерфейс и поведение заказа остаются стабильными.

## Поведение интерфейса

- Если возможность выключена, связанный функционал не показывается в пользовательских сценариях и административных разделах.
- Если возможность включена, но модуль технически не установлен, административный раздел может показывать экран установки/подготовки модуля.
- Если возможность включена и модуль установлен, функционал работает в полном режиме.

## Примеры возможностей

- `Шкафчики` — выбор ячеек при бронировании, администрирование шкафчиков и интеграция с WebIO/iCal.
- `WebIO` — управление внешними устройствами и портами.
- Другие опциональные сценарии, которые должны включаться только для части сайтов.
