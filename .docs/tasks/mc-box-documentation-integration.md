# Интеграция документации ветки mc_box

> **Статус:** в работе  
> **Область:** Composer, документация и функциональные изменения ветки `mc_box`  
> **Последняя проверка:** 2026-08-24  
> **Связанный код:** ветки `dev` и `mc_box`

## Цель

Перенести полезные дополнения `mc_box` в текущую структуру документации без возврата устаревших каталогов `.docs/reports/`, `.docs/report_cursor/`, `.docs/promt/` и legacy-списков задач.

## Правило объединения

`dev` является источником истины для структуры и навигации документации. Содержательные дополнения `mc_box` переносятся по доменам и только после проверки соответствия коду целевой ветки. Полная замена каталога `.docs/` или merge с выбором версии одной стороны не допускается.

## Переносить вместе с кодом

### Lockers

В `dev` пока нет `core/modules/lockers/`, поэтому модульный документ `mc_box:.docs/modules/lockers/README.md` не публикуется как описание текущей реализации.

После переноса кода необходимо:

1. Создать краткий `.docs/modules/lockers/README.md`.
2. Сохранить подробное описание реализации отдельным тематическим файлом.
3. Перенести схемы, правила доступности и WebIO-интеграцию из `.docs/tasks/lockers/` в модульный раздел.
4. Оставить в `.docs/tasks/lockers/locker-system-plan.md` только незавершённые этапы.
5. Обновить реестры модулей и задач.

### Файловые транспорты

Документ `mc_box:.docs/technical/file-transports.md` описывает `FileTransportInterface`, `FileTransportFactory` и `DeployFile::deployContentsBatch()`, которых пока нет в `dev`. Документ переносится вместе с этими API и их тестами.

## Не переносить

- `.docs/development/git-commit-message.md` является prompt-файлом, а не проектной документацией. Правила коммитов уже определены в `AGENTS.md` и skill `git-commits`.
- Старые индексы `.docs/README.md`, `.docs/modules/README.md` и содержимое legacy-каталогов не должны заменять актуальные индексы `dev`.
- Отчёты из `.docs/reports/` и `.docs/report_cursor/` остаются в текущем `.docs/archive/reports/`.

## Следующие доменные этапы

1. Перенести код и документацию файловых транспортов.
2. Перенести модуль lockers и преобразовать его длинный план в модульное описание и короткий остаточный план.
3. Сверить изменения `webIo`, `clients`, `config` и `reservations` по общему предку веток.
4. После каждого этапа запускать `composer docs:check` и профильные тесты.

## Критерии завершения

- все перенесённые документы описывают код ветки `dev`;
- дополнительные документы включены в профильные `README.md`;
- активные и завершённые задачи не смешиваются;
- проверка `composer docs:check` проходит;
- старые каталоги документации не восстановлены.
