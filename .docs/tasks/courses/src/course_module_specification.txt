1. Общая архитектура
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

Модуль реализует курс как логическую группу бронирований (reservations).  
Каждое занятие — это обычная запись в `at_base_active_court_reservations`,  
связанная с курсом через таблицу `course_reservations`.

Преимущества:
- Используется существующая логика проверки занятости (blocks, tickets, reservations).
- Курсы отображаются в календаре площадок, если не выбран «Anderer Ort».
- Оплата интегрирована через `accounts`, `private_account_transactions`.
- Нет дублирования данных: площадка, время, клиент — берутся из `reservations`.

Минусы (сознательные):
- Для фильтрации курсов требуется JOIN с `course_reservations`.
- Тип брони остаётся `type_reservation = 1` — метка «курс» хранится в связях, а не в enum.

2. Жизненный цикл курса
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

2.1. Создание курса (админ)
- Вводится: название, описание, изображение, тренер (client_id), площадка (area_id).
- Выбираются даты → для каждой создаётся запись в `reservations` (client_id = trainer или 0).
- Для каждой даты проверяется доступность через стандартную логику:
    • blocks (area_id + start/finish)
    • tickets (клиент + area + время)
    • reservations (area + время)
- Если занято — админ видит причину, но может игнорировать (риск перебронирования).
- Добавляются цены в `course_prices`.
- При создании курса автоматически:
    • создаётся 1 запись в `course_groups`,
    • N записей в `course_reservations` (N = кол-во занятий).

2.2. Участие пользователя
- Пользователь заходит на страницу курса → видит:
    • описание, фото, тренера, место, даты, цены.
- Если `is_sessions_bookable_separately = 0`: только кнопка «Забронировать весь курс».
- Если `= 1`: чекбоксы на будущие даты + расчёт суммы.
- При подтверждении:
    • создаётся счёт (`accounts.account_type = '2'`);
    • для каждой даты создаётся reservation (client_id = участник);
    • связь с курсом добавляется в `course_reservations` (с `is_full_course_reservation = '1'` или `'0'`);
    • если оплата — Guthaben: проверяется баланс через `private_account_transactions`;
    • если оплата — PayPal: допускается только при self-booking;
    • отправляется письмо через шаблон `kurs-confirmation`.

2.3. Ручное управление (админ/тренер)
- Админ может:
    • добавить участника → создаётся reservation + связь;
    • изменить цену → запись в `course_participant_overrides`;
    • ограничить доступ к занятиям → записи в `course_participant_allowed_sessions`;
    • удалить дату → reservation помечается как отменённая (status='0'), но не удаляется;
    • отменить курс → status='cancelled' в `course_groups`, уведомление по `kurs-cancellation`.
- Возврат средств производится вручную через интерфейс счёта.

3. Права доступа
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- **Админ (users.rights = '3')** — полный контроль.
- **Kurs-Admin (Level 4)** — реализуется через таблицу `user_course_roles`.
    Доступны только курсы, где:
        EXISTS (SELECT 1 FROM user_course_roles WHERE user_id = ? AND course_group_id = ?)
    Права:
        • редактировать даты;
        • добавлять/удалять участников;
        • отправлять уведомления;
        • просматривать список.
    Запрещено:
        • создавать новые курсы;
        • менять цены, тренера, площадку;
        • управлять финансами напрямую.

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
4. Уведомления
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- Отправляются из админки/тренерки → всем участникам курса.
- Используются шаблоны из `letters_templates` (алиасы: kurs-*).
- Перед отправкой — диалог: «Был ли отредактирован шаблон письма?» → запись в `was_edited`.
- Логирование в `course_notifications_log` для аудита.

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
5. Отображение
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

5.1. В календаре площадок
- Занятия курса отображаются цветом (например, синим).
- При наведении — всплывает название курса.
- Клик → переход на детальную страницу курса.
- Если `is_other_location = 1` — записи в календаре НЕ отображаются.

5.2. Страница курса (публичная)
- URL: /kurse/{course_group_id}
- Поля:
    • title, description, image_path
    • trainer: name + surname (JOIN clients)
    • area: title (JOIN areas)
    • dates: список из `reservations` + статус (активно/отменено)
    • prices: из `course_prices`
    • кнопка бронирования (активна, если мест < max_participants)

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
6. Отмена и возвраты
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- Участник может отменить:
    • весь курс → удаляются все его reservation (status='0');
    • отдельное занятие → только если `is_sessions_bookable_separately = 1`.
- Проверка срока отмены: 
    NOW() < (start - INTERVAL course_group.cancel_days_limit DAY)
- Возврат средств — только вручную админом через интерфейс счёта.
- Система НЕ делает автоматические возвраты — это требование ТЗ.

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
7. Особые условия (по ТЗ)
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

✅ Лист ожидания — отсутствует.  
✅ Сезоны, скидки, спеццены — не используются.  
✅ Одно изображение — только в `image_path`.  
✅ Цена фиксируется при бронировании (в счёте).  
✅ Удаление дат не влияет на цену уже оплаченных курсов.  
✅ PayPal — только при self-booking (проверка: created_by_user_id ≠ admin).  
✅ Guthaben — проверка баланса перед созданием счёта.

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
8. Метрики и отчёты
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- Кол-во участников: 
    SELECT COUNT(*) FROM course_reservations cr
    JOIN reservations r ON r.reservation_id = cr.reservation_id
    WHERE cr.course_group_id = ? AND r.status = '1'

- Занятость площадки на дату:
    Используется стандартный запрос — курсовые брони учитываются автоматически.

- Доход по курсу:
    SELECT SUM(a.abo_sum) FROM accounts a 
    JOIN course_groups cg ON a.info LIKE CONCAT('Kurs: ', cg.course_group_id, '%')
    WHERE cg.course_group_id = ? AND a.closed = '0'

9. Интеграции
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- PayPal: через `reservations_tmp_paypal` → как обычные брони.
- Дверные коды: `reservations.door_code` заполняется при бронировании.
- Учёт света/тепла: `reservations.light_state`, `heating_state` — как обычно.
- Логирование: `reservation_data` можно использовать для доп. параметров (опционально).

■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■
10. Что НЕ входит в MVP
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■

- Автоматические напоминания (за 1 день до занятия).
- Повторяющиеся курсы (еженедельные, ежемесячные).
- Мультиязычность шаблонов (только немецкий).
- Мобильная адаптация интерфейса (только backend).
- API для интеграции с внешними системами.
