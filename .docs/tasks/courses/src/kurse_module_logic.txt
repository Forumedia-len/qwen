МОДУЛЬ ГРУППОВЫХ ЗАНЯТИЙ (KURSE / EVENTS)
Логика работы — версия 1.2 (с поддержкой "Anderer Ort" и персонализации по занятиям)

■■■■■■■ 1. ОБЩАЯ АРХИТЕКТУРА ■■■■■■■

Курс = логическая группа бронирований (reservations), связанных через course_reservations.
→ Каждое занятие — обычная запись в at_base_active_court_reservations.
→ Все механизмы проверки (blocks, tickets, availability) работают как раньше.

Преимущества:
• Нет дублирования данных (время, площадка, цена света — из reservations).
• Оплата через accounts, private_account_transactions — без изменений.
• Совместимость с календарём, дверными кодами, светом/теплом.

Ограничения:
• Тип брони остаётся type_reservation = 1 — «курс» определяется по наличию связи в course_reservations.
• Финансовая привязка: accounts.info LIKE 'Kurs: %' — для отчётов.

■■■■■■■ 2. "ANDERER ORT" — КУРС БЕЗ ПЛОЩАДКИ ■■■■■■■

Требование: курс может проходить вне зарегистрированных мест.

Решение:
• В course_groups.area_id = NULL и is_other_location = '1'.
• В reservations.area_id = 99999 — виртуальная площадка "Anderer Ort".
• Площадка 99999:
   – Существует физически в таблице areas (вставляется один раз).
   – Не отображается в календаре (UI фильтрует: WHERE area_id != 99999).
   – Не имеет цен, абонементов, блокировок — безопасна.
   – Используется только модулем Kurse.

Логика при создании:
1. Админ выбирает «Anderer Ort».
2. course_groups.area_id = NULL, is_other_location = '1'.
3. Для каждой даты создаётся reservation с area_id = 99999.

■■■■■■■ 3. ЦЕНОВАЯ ЛОГИКА ■■■■■■■

3.1. Базовые цены — course_prices
• Таблица нормализована: (course_group_id, membership_type_id) → (price_full, price_single).
• Поддерживает неограниченное число типов членства (membership_type_id ссылается на membership_types).
• NULL = курс недоступен; 0.00 = бесплатно.

3.2. Глобальная скидка — course_participant_overrides (reservation_id = NULL)
• Участник X получает скидку на ВЕСЬ курс: price_full_override = 75.00.
• Действует при любом способе бронирования (полный курс или по частям).

3.3. Скидка на отдельное занятие — course_participant_overrides (reservation_id = N)
• Строка с reservation_id = 1005 → цена за занятие 1005 для участника X = price_single_override.
• Может быть несколько строк на одного участника → разные цены за разные занятия.

Приоритет расчёта цены (на одно занятие):
1. course_participant_overrides.price_single_override (если reservation_id совпадает)
2. course_participant_overrides.price_full_override (если reservation_id IS NULL)
3. course_prices.price_single (по типу членства)
→ Если все NULL — недоступно.

■■■■■■■ 4. УПРАВЛЕНИЕ УЧАСТНИКАМИ ■■■■■■■

4.1. Добавление участника
• Админ/тренер добавляет вручную → создаётся reservation + связь в course_reservations.
• Цена определяется по приоритету (см. выше).
• Если payment_type = 'trainer' → счёт создаётся на тренера; участникам encash = '2' (Guthaben), но списания нет.

4.2. Ограничение доступа к занятиям
• При is_sessions_bookable_separately = '1':
   – Если allowed_sessions пусто → доступны ВСЕ занятия.
   – Если есть записи → только указанные reservation_id.
• Используется для: пробных, пропущенных, специальных занятий.

■■■■■■■ 5. ПРАВА ДОСТУПА ■■■■■■■

• Kurs-Admin (через user_course_roles):
   – Может добавлять/удалять даты, участников, отправлять уведомления.
   – Может менять цены ТОЛЬКО через course_participant_overrides (не глобально!).
   – НЕ может изменять: тренера, площадку, payment_type, базовые цены.

Проверка в коде:
  EXISTS (SELECT 1 FROM user_course_roles WHERE user_id = ? AND course_group_id = ?)

■■■■■■■ 6. ОПЛАТА ■■■■■■■

■■■■■■■ 8. ОТОБРАЖЕНИЕ ■■■■■■■

• В календаре: курсовые брони отображаются цветом, клик → страница курса.
• Если is_other_location = '1' → записи НЕ отображаются (фильтр: area_id != 99999).
• Страница курса (/kurse/{id}):
   – title, description, image_path
   – тренер (JOIN clients)
   – место: если area_id = 99999 → «Anderer Ort», иначе areas.title
   – даты: из reservations (JOIN course_reservations)
   – цена: по текущему клиенту (тип членства + overrides)

■■■■■■■ 9. ОТМЕНА ■■■■■■■

• Участник может отменить:

• Проверка: NOW() < (start - INTERVAL cancel_days_limit DAY)
