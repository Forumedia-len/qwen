
МОДУЛЬ ГРУППОВЫХ ЗАНЯТИЙ (KURSE)
ДЕТАЛЬНОЕ ОПИСАНИЕ ПРОЦЕССА РЕГИСТРАЦИИ КЛИЕНТОВ НА КУРСЕ
Версия: 1.3 (с поддержкой "Anderer Ort", частичного бронирования и персонализации цен)
Дата: 20 декабря 2025 г.
Автор: Системный архитектор

■■■■■■■ 1. ОБЩАЯ МОДЕЛЬ ■■■■■■■

Курс — это логическая группа бронирований.  
Каждое занятие = запись в `at_base_active_court_reservations`.  
Регистрация клиента = создание новых записей в `reservations` + связь через `course_reservations`.

→ Нет новых сущностей для бронирования.  
→ Полная совместимость с существующей проверкой занятости, дверными кодами, светом и т.д.

■■■■■■■ 2. УСЛОВИЯ РЕГИСТРАЦИИ ■■■■■■■

Регистрация возможна только если:
- `course_groups.status = 'active'`;
- дата занятия > NOW();
- количество активных участников < `course_groups.max_participants`;
- клиент авторизован;
- `reservations.status = '1'` для выбранной даты (не отменена).

Если `is_other_location = '1'` — площадка `99999`, и она **исключается из календаря**, но бронирование разрешено.

■■■■■■■ 3. ДВА СПОСОБА РЕГИСТРАЦИИ ■■■■■■■

| Способ | Кто | Условия | Особенности |
|--------|-----|---------|-------------|
| **3.1 Самостоятельная регистрация** | Любой `client_id`, авторизованный на сайте | • Только через UI `/kurse/{id}`,• Только будущие даты,• Только активные курсы | • PayPal разрешён,• Цена фиксируется автоматически,• Персонализацию может добавить только позже тренер/админ |
| **3.2 Ручная регистрация** | Админ (`rights = '3'`) или Kurs-Admin (`user_course_roles`) | Без ограничений по времени и лимитам | • Можно установить `price_full_override` / `price_single_override` сразу,• Можно ограничить доступ к занятиям через `course_participant_allowed_sessions`,• PayPal **недоступен** (т.к. `created_by_user_id ≠ client.user_id`) |

■■■■■■■ 4. ПОШАГОВЫЙ АЛГОРИТМ РЕГИСТРАЦИИ ■■■■■■■

### Шаг 1. Выбор дат
- Пользователь заходит на `/kurse/{course_group_id}`.
- Отображаются:
  - Все даты курса с `reservations.status = '1'` и `start > NOW()`.
  - Если `is_sessions_bookable_separately = '0'` — только кнопка **«Забронировать весь курс»** (все даты автоматически выбраны).
  - Если `'1'` — чекбоксы на каждую будущую дату + кнопка **«Забронировать выбранные»**.
- Прошедшие, отменённые и заблокированные даты не отображаются.

### Шаг 2. Расчёт итоговой суммы
Система **по каждой дате** определяет цену с приоритетом:

| Приоритет | Условие | Источник | Действие |
|-----------|---------|----------|----------|
| **1** | существует запись в `course_participant_overrides` с совпадающими `course_group_id`, `client_id`, `reservation_id` | `price_single_override` | Берётся её значение |
| **2** | существует запись с `reservation_id IS NULL` | `price_full_override` | Для курса в целом. **Если выбраны НЕ ВСЕ даты — используется как сумма за курс, а не за занятие** |
| **3** | базовая цена по типу членства | `course_prices.price_single` (если частично) или `price_full` (если весь курс) | Стандартная цена |
| **4** | иначе | `NULL` | Занятие недоступно для данного типа членства |

> ⚠️ Особый случай:  
> Если `is_sessions_bookable_separately = '0'`, но пользователь выбрал не все даты (например, одна дата уже отменена), система **всё равно считает как полный курс**, но исключает отменённые даты из бронирования. Цена берётся из `price_full` или `price_full_override`.

### Шаг 3. Создание счёта (`accounts`)
- `account_type = '2'` (Other)
- `info = 'Kurs: {course_group_id}'`
- `abo_sum` = итоговая сумма (фиксированная, не меняется при изменении курса)
- `client_id` = ID участника
- `account_id` генерируется

#### Определение способа оплаты (`encash`):
| Настройка курса | Действие |
|-----------------|----------|
| `payment_type = 'self'` | • Доступны: BAR (`0`), RE (`1`), GH (`2`), PP (`3`)*, EC (`4`),• *PP — только если `created_by_user_id = client.user_id` (т.е. самостоятельная регистрация) |
| `payment_type = 'trainer'` | • `encash = '2'` (GH),• **Счёт создаётся на тренера** (`client_id = trainer_client_id`),• Участнику — только бронь без оплаты |
| `payment_type = 'free'` | • Счёт **не создаётся** (или `abo_sum = 0.00`, `encash = '0'`, флаг в `info`) |

#### Проверка Guthaben (если `encash = '2'`):
```sql
SELECT COALESCE(SUM(amount), 0)
FROM at_base_active_court_private_account_transactions
WHERE client_id = ? AND status = 'succeeded';
```
- Если баланс < `abo_sum` → система предлагает:
  - переключиться на Rechnung (`encash = '1'`), **ИЛИ**
  - пополнить баланс.

### Шаг 4. Создание бронирований (`reservations`)
Для **каждой выбранной даты** создаётся запись в `reservations` со следующими параметрами:

| Поле | Значение | Комментарий |
|------|----------|-------------|
| `area_id` | `course_groups.area_id` (если не NULL), иначе `99999` | Виртуальная площадка «Anderer Ort» |
| `client_id` | ID участника | — |
| `type_reservation` | `1` | simple |
| `encash` | как в счёте | — |
| `start`, `finish` | копируются из исходной брони курса | та, что создал админ при настройке курса |
| `light_state`, `heating_state`, `net_state` | копируются из исходной брони | — |
| `door_code` | копируется из исходной брони | — |
| `status` | `'1'` | активно |
| `ordered` | `NOW()` | — |

> 💡 Все брони курса изначально создаются админом с `client_id = trainer_client_id` или `0`.  
> При регистрации участника создаются **новые** записи — исходные **не меняются**.

### Шаг 5. Связь с курсом (`course_reservations`)
Для каждой новой брони создаётся запись в `course_reservations`:

| Поле | Значение | Комментарий |
|------|----------|-------------|
| `course_group_id` | ID курса | — |
| `reservation_id` | ID новой брони | — |
| `is_full_course_reservation` | `'1'`, если:,• выбраны **все** будущие даты курса,,• `is_sessions_bookable_separately = '0'`,Иначе — `'0'` | Нужно для отчётов и UI |

### Шаг 6. Персонализация (необязательно)
Если цена отличается от базовой, создаётся запись в `course_participant_overrides`:

| Сценарий | `reservation_id` | `price_full_override` | `price_single_override` | `created_by_user_id` |
|----------|------------------|------------------------|--------------------------|----------------------|
| Полный курс | `NULL` | сумма | `NULL` | `client.user_id` (самостоятельно) или `user_id` (админ/тренер) |
| Одно занятие | `reservation_id` | `NULL` | цена занятия | — |
| Несколько занятий с разными ценами | несколько строк | — | разные значения | — |

> ⚠️ В `create.txt` изначально был `UNIQUE(course_group_id, client_id)`, но в расширенной логике он **удалён**, чтобы разрешить несколько override-записей на одного участника.

### Шаг 7. Ограничение доступа к занятиям (если требуется)
Если `is_sessions_bookable_separately = '1'` и админ хочет ограничить доступ:
- Создаётся запись в `course_participant_overrides`;
- Для каждой разрешённой даты — запись в `course_participant_allowed_sessions`:
  ```sql
  INSERT INTO course_participant_allowed_sessions (override_id, reservation_id)
  VALUES (?, ?);
  ```
- При бронировании проверяется:  
  `reservation_id IN (SELECT reservation_id FROM course_participant_allowed_sessions WHERE override_id = ?)`

### Шаг 8. Отправка уведомления
- Отправляется письмо по шаблону `kurs-confirmation`.
- Подстановки:
  - `{name}` → `clients.name + ' ' + clients.surname`
  - `{course_title}` → `course_groups.title`
  - `{dates}` → список дат в формате `DD.MM.YYYY HH:MM`, через запятую
  - `{price}` → `abo_sum`
- Логируется в `course_notifications_log`.

■■■■■■■ 5. ПРИМЕРЫ ■■■■■■■

### Пример 1. Самостоятельная регистрация на весь курс
- Клиент: Mitglied V1 (`membership_type_id = 1`)
- Курс: `price_member_v1_full = 120.00`
- Даты: 3 занятия (10.01, 17.01, 24.01)
- Способ оплаты: PayPal
- Действия:
  1. Создаётся счёт: `account_type = '2'`, `abo_sum = 120.00`, `encash = '3'`, `info = 'Kurs: 45'`
  2. Создаются 3 записи в `reservations`
  3. 3 записи в `course_reservations` с `is_full_course_reservation = '1'`
  4. Письмо: «Вы забронировали курс „Tennis für Anfänger“ на 10.01, 17.01, 24.01. Цена: 120.00 €»

### Пример 2. Ручная регистрация с персонализацией
- Админ добавляет участника на 2 из 6 занятий.
- Устанавливает:  
  `price_single_override = 10.00` для занятия 10.01,  
  `price_single_override = 15.00` для занятия 17.01.
- Действия:
  1. Создаётся счёт на 25.00 €
  2. 2 записи в `reservations`
  3. 2 записи в `course_reservations` с `is_full_course_reservation = '0'`
  4. 2 записи в `course_participant_overrides` (с разными `reservation_id`)
  5. 2 записи в `course_participant_allowed_sessions`

### Пример 3. Курс с «Anderer Ort»
- `course_groups.area_id = NULL`, `is_other_location = '1'`
- Все брони курса: `reservations.area_id = 99999`
- В календаре площадок такие брони **не отображаются** (UI фильтрует `WHERE area_id != 99999`)
- В деталях курса: вместо названия площадки — текст *„Anderer Ort“*

■■■■■■■ 6. КОНТРОЛЬНЫЕ ТОЧКИ ■■■■■■■

| Место | Проверка |
|-------|----------|
| UI | Отключена кнопка «Забронировать», если `max_participants` достигнут |
| Backend | Перед созданием брони: проверка `COUNT(active participants) < max_participants` |
| Оплата | При GH — проверка баланса; при PP — проверка `created_by_user_id = client_id` |
| Безопасность | У тренера — только `INSERT/UPDATE` в `course_participant_overrides`, но не в `course_prices` |
| Целостность | `ON DELETE CASCADE` во всех FK — при удалении курса удаляются и связи |

■■■■■■■ 7. ОТМЕНА РЕГИСТРАЦИИ ■■■■■■■

- Участник может отменить:
  - весь курс → все его `reservations.status = '0'`
  - отдельное занятие → только если `is_sessions_bookable_separately = '1'`
- Проверка срока:  
  `NOW() < (start - INTERVAL course_groups.cancel_days_limit DAY)`
- Возврат — только вручную админом через интерфейс счёта.

■■■■■■■ 8. ТЕХНИЧЕСКИЕ ЗАМЕЧАНИЯ ■■■■■■■

- **Где хранится «это — курс»?**  
  Только через `course_reservations`. В `reservations` — нет флага.

- **Как отличить курс от обычной брони?**  
  ```sql
  SELECT cr.course_group_id
  FROM reservations r
  LEFT JOIN course_reservations cr USING (reservation_id)
  WHERE r.reservation_id = ?;
  ```

- **Как показывать «Kurs» в интерфейсе?**  
  Если `cr.course_group_id IS NOT NULL` → отображать название курса и тренера, а не площадку.

- **Логирование доп. данных**  
  Можно использовать `reservation_data` (уже есть в БД) для хранения:
  - `type_block = 'course'`, `name = 'override_source'`, `value = 'trainer_discount'`
  — без изменения схемы.

■■■■■■■ ЗАКЛЮЧЕНИЕ ■■■■■■■

Регистрация на курс — это **расширенная версия стандартного бронирования**, полностью интегрированная в текущую архитектуру:
- Не требует новых типов счётов, оплат, проверок.
- Гибкость достигается через связи и персонализацию.
- Совместима со всеми существующими механизмами (Guthaben, PayPal, свет, двери).
