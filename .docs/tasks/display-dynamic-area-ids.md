# Динамический список площадок дисплея

> **Статус:** запланировано  
> **Область:** информационный дисплей  
> **Последняя проверка:** 2026-08-24  
> **Связанный код:** `assets/display/js/ajaxloadmodule.js` в репозитории конкретного сайта

## Проблема

Сейчас JavaScript содержит фиксированный список площадок:

```js
var areas = Array(1, 2, 11, 12, 13, 14, 15, 16, 17, 18)
```

Список не синхронизируется с базой данных, настройкой `DISPLAY_TYPE` и правилами видимости для устройства `display`. Новая, отключённая или скрытая правилом площадка может обрабатываться неправильно, пока массив не будет изменён вручную.

Кроме того, `display/reservations_visualization.php` самостоятельно запрашивает типы `1` и `2`. HTML-страница при этом строит список типов из `DISPLAY_TYPE` и применяет правила отображения в `ReservationsVisualizationCommon::getAreasColumn()`. В результате набор площадок в HTML и XML может различаться.

## Цель

Сделать базу данных, конфигурацию типов и серверные правила единственным источником доступных площадок. JavaScript должен автоматически обрабатывать только те площадки, которые сервер разрешил и вывел на дисплей.

## Предлагаемая реализация

### 1. Динамическое определение площадок в браузере

После построения DOM и до первого вызова `start()` собрать уникальные `area_id` из элементов с ID формата `timeBox_{area_id}_{period_number}`.

Требования:

- сохранить порядок колонок в HTML;
- исключить дубликаты;
- принимать только числовой `area_id`;
- не запускать обработку панелей, если площадок нет;
- учитывать поддержку старых браузеров: не применять `Set`, `Array.from` и другие конструкции без полифилов, пока не подтверждены требования к браузеру дисплея.

Вариант, совместимый с используемым стилем jQuery:

```js
var areas = []

function collectAreaIds () {
  areas = []

  $('[id^="timeBox_"]').each(function () {
    var match = this.id.match(/^timeBox_(\d+)_\d+$/)
    var areaId = match ? parseInt(match[1], 10) : null

    if (areaId !== null && $.inArray(areaId, areas) === -1) {
      areas.push(areaId)
    }
  })
}
```

В `document.ready` порядок запуска должен быть следующим:

1. Вызвать `collectAreaIds()`.
2. Вызвать `start()` только при `areas.length > 0`.
3. Запустить часы независимо от наличия площадок.

Список, полученный из DOM, уже прошёл серверные проверки при построении HTML. Он используется для управления интерфейсом, но не считается механизмом авторизации.

### 2. Единая серверная фильтрация HTML и XML

XML-обработчик должен использовать те же сочетания `type_id`/`sport_id` и те же правила видимости, что страница дисплея.

Предпочтительный вариант:

1. Вынести определение типов дисплея из `display/index.php` в общий метод или сервис.
2. Вынести получение разрешённых для `display` площадок в переиспользуемый серверный метод.
3. Использовать эти методы и при построении HTML, и в `reservations_visualization.php`.
4. Перед формированием XML отфильтровать результаты `getPeriodsByAreasTypeDate()` по разрешённым `area_id`.

Серверная проверка должна учитывать как минимум:

- `areas.active = 1`;
- соответствие настроенным `type_id` и `sport_id`;
- приоритетное правило площадки через `rulePriority()`;
- видимость колонки для устройства `display` через `getVisibleColumnByRule()`;
- порядок площадок, определённый базой данных.

Если обработчик когда-либо начнёт принимать список ID от браузера, этот список разрешается использовать только для сужения результата. Сервер обязан пересечь его со своим списком разрешённых площадок; клиентские данные не могут предоставлять доступ.

### 3. Формат ответа

Существующий формат элементов `<period>` и их ID необходимо сохранить, чтобы не ломать текущую визуализацию:

```xml
<period id="timeBox_12_1" start="08:00" finish="08:30" ... />
```

Добавлять отдельный список площадок в XML для этой задачи необязательно: порядок и состав панелей берётся из HTML. Главное требование к XML — отсутствие периодов площадок, скрытых серверными правилами.

## Затрагиваемые файлы

- `assets/display/js/ajaxloadmodule.js` в репозитории сайта — динамический сбор ID и безопасный запуск панелей.
- `display/index.php` — использование общего источника типов дисплея.
- `display/reservations_visualization.php` — использование настроенных типов и фильтрация разрешённых площадок.
- `core/ReservationsVisualizationCommon.php` либо новый общий сервис — переиспользуемое получение типов и разрешённых площадок.

Серверные изменения выполняются в этом общем репозитории. Изменение JavaScript выполняется в репозитории сайта; копировать серверные файлы в сайт не требуется.

## Критерии приёмки

- В JavaScript отсутствует фиксированный список `area_id`.
- Активная и разрешённая площадка автоматически появляется на дисплее без изменения JavaScript.
- Неактивная площадка не появляется в HTML и XML.
- Площадка, скрытая правилом для устройства `display`, отсутствует в HTML и XML.
- Изменение `DISPLAY_TYPE` одинаково влияет на HTML и AJAX-ответ.
- Порядок анимации совпадает с порядком колонок на странице.
- При отсутствии доступных площадок нет JavaScript-ошибок и бесконечного вызова `startPanel()`.
- Текущие статусы периодов и интервал обновления 30 секунд продолжают работать.
- Формат существующих XML-элементов `<period>` остаётся обратно совместимым.

## Сценарии проверки

1. Открыть дисплей с текущей конфигурацией и убедиться, что все видимые колонки обновляются.
2. Добавить активную площадку разрешённого типа и проверить её появление без правки JavaScript.
3. Отключить площадку в базе и проверить её отсутствие после перезагрузки страницы.
4. Скрыть площадку правилом `show_on`/видимости для `display` и проверить HTML и XML.
5. Изменить `DISPLAY_TYPE` на другой набор типов и проверить совпадение HTML с XML.
6. Проверить страницу при нулевом количестве разрешённых площадок.
7. Проверить свободный, прошедший, заблокированный, ожидающий подтверждения и занятый периоды.

## Вне рамок задачи

- Изменение визуального дизайна дисплея.
- Переименование исторического CSS-класса `avaliable`.
- Изменение интервала AJAX-обновления.
- Общий рефакторинг устаревшего `XMLHttpRequest` и анимаций jQuery.
