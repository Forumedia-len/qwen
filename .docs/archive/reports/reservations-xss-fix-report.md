# Исправление XSS на странице бронирования

Дата: 2026-09-10. Изменения выполнены в текущих рабочих деревьях `base-active-court` и `cdn`.
Коммиты, переключение веток и установка на production не выполнялись.

## Причина и исправление

Исходный PoC с параметром `date` воспроизводился на `tennisbuchung-test.loc`:
браузер выполнял `alert('OPENBUGBOUNTY')`. Точка внедрения находилась в общем шаблоне
`app/tpl/site/_auth.php`, где GET-параметр вставлялся в `value` скрытого поля без кодирования.
Скрытие окна входа через CSS не мешало выполнению внедрённого HTML.

Дополнительно были воспроизведены аналогичная инъекция через `type_id` с числовым префиксом
и вставка JavaScript через `tab` (GET/POST). Последняя затрагивала и `index.php`, поскольку форма входа общая.
Перед исправлением непустой `date[]` приводил к HTTP 500.

Внедрён метод `Service::request()->validated($alias, $source, $rules, $default = null)`.
Он использует существующие валидаторы через отдельный `Service::validation(false)` в строгом режиме.
Поведение старых методов чтения запроса и старого режима валидации сохранено.
При неверном вводе приложение возвращает HTTP 400 и локализованный простой текст без отражения исходного значения.

Защита применяется в двух местах: проверка структуры/типа до обработки и кодирование непосредственно при выводе.
Это соответствует разделению контекстов в
[OWASP XSS Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html).

| Область | Что изменено |
|---|---|
| Общая форма входа | Проверка `date`, `type_id`, `tab`; кодирование скрытых полей и данных гостевой сессии. |
| Инициализация вкладки | Проверенное `0|1` передаётся через `data-auth-tab`; прямой вставки в JavaScript больше нет. |
| Бронирование | Проверяются дата, идентификаторы, страница, неделя, время и все ключи массива выбранных периодов. |
| Даты | Сохранены `Y-m-d` и `d.m.Y`; неверная календарная дата не преобразуется через `strtotime()` в другую дату. |
| Форма подтверждения | Кодируются атрибуты скрытых полей; строковый `memo` сохраняет исходный текст. |
| Имена | Кодируются имя в шапке, игроки в select и имя второго игрока открытого корта. |
| Вход | Поля проверяются как строки, пароль не обрезается и не HTML-кодируется; redirect собирается через `http_build_query()`. |
| WebIo | Для активных состояний проверяется карта временных ключей и флагов. |
| AJAX | Цена и время вставляются через `.text()`, исключая интерпретацию HTML ответа. |
| Совместимость | В строгом режиме исправлены небезопасные приведения bool/float и переполнение integer; старый режим сохранён. |

В CDN также добавлена проверка пустого списка колонок и нечислового cookie в `columnOffset()`:
обнаруженная до изменения ошибка `offsetLeft` больше не прерывает инициализацию недельной страницы.

## Проверка

Использовались PHP 8.2.26 и установленный Google Chrome в headless-режиме с CDP.
Реальный сайт проверялся на `https://tennisbuchung-test.loc/`.

| Проверка | Результат |
|---|---|
| Синтаксис и diff | Все 21 изменённый/новый PHP-файл проходят `php -l`; оба JS-файла проходят `node --check`; `git diff --check` чистый в обоих репозиториях. |
| 68 проверок PHP | Пройдены: вредоносные значения, скаляр/массив, диапазоны, переполнение, даты, время, default/required, alias, источники и совместимость. |
| 30 браузерных сценариев | Выполнение внедрённого JavaScript не обнаружено; исходный PoC и 19 других неверных запросов получили HTTP 400. |
| `date`, `type_id`, `tab` | Исходная атака, разрыв HTML/JS-контекста, GET/POST, массивы и вложенные массивы блокируются. |
| Другие URL-параметры | Проверены атаки через `sport_id`, `area_id`, `page`, `week`, `time`; неиспользуемые `need`/`other` не отражают HTML. |
| Корректные сценарии | День, неделя, обе формы даты, общая страница входа и допустимые значения `tab` возвращают HTTP 200. |
| Вход игрока | `test_fm`: успешный вход, сохранение выбранной даты, открытие подтверждения и выход. |
| Расчёт цены | HTTP 200 с JSON; дата из реальной формы `11.09.2026` принимается, цена обновляется в DOM. |
| Комментарий | HTML в строковом `memo` не исполняется; `memo[]` получает HTTP 400. |
| Защита DOM | Подстановка тестового HTML в ответ цены/времени отображается текстом, не создаёт `img` и не вызывает alert. |
| Изолированные шаблоны | Реальные `_auth.php`, `_choice_players.php`, `_proceed_order_hidden_input.php` отрисованы с вредоносными данными без БД; в Chrome ввод остаётся текстом. |
| Размер страницы | Для расписания: 320/768/1440/1920 px; для подтверждения: 320/768/1440 px. Горизонтального скролла документа нет. |

В исправленных браузерных сценариях расписания и формы подтверждения исключений JavaScript не обнаружено.
Для проверки DOM-вывода AJAX использовалась также искусственная подстановка ответа; это отдельная проверка
обработчика вывода, а не подтверждение возможности управлять настоящим серверным ответом.

## Границы проверки

- Конфигурация локального сайта указывает на базу `at_mainz` и `BASE_HREF` с алиасом `tennisbuchung-mainz.loc`.
  Настройки и эталонная база `at_base_active_court` не переключались. При проверке AJAX базовый URL только
  в тестовом DOM был направлен на `tennisbuchung-test.loc`, чтобы не уходить на соседний хост.
- На этой установке гостевой вход и открытые/двойные корты не представлены полным рабочим сценарием.
  Гостевые поля и список игроков проверены отдельно на реальных шаблонах с тестовыми объектами в памяти.
  Имена в шапке и имя второго игрока проверены по коду; вредоносные записи в БД не создавались.
- Неактивные входные поля WebIo игнорируются этой конфигурацией; их тестовые значения не отражаются в JSON.
  Строгая проверка активной карты покрыта PHP-проверками валидатора.
- Подтверждение с созданием брони, списание денег, отправка писем и внешние платёжные системы не запускались.
  Проверка остановлена перед финальной операцией. Собственная временная блокировка выбранного периода очищена.
- На первом этапе соседний репозиторий `../tests/` отсутствовал. Codeception тогда не запускался; проверки PHP и браузера выполнены
  временными сценариями вне репозитория приложения. Эти сценарии, результаты и профили Chrome удалены после проверки.
  На первом этапе `php bin/check-documentation` обнаружил только три существующие ссылки на отсутствующий `tests/README.md`
  в `.docs/development/testing.md` и `.docs/archive/tasks/scoped-config-implementation.md`.
- Это проверка страницы бронирования и общих компонентов, задействованных в ней; она не является полным аудитом
  всех административных, платёжных, API и терминальных интерфейсов проекта.
- Production Schlenter-Arena и другие установки не тестировались. Исправление общего компонента применимо
  к установкам с этим кодом, но их фактическая уязвимость и состояние развёртывания отдельно не подтверждены.

проверка количества строк каждой скопированной таблицы и неизменности метаданных источника прошла успешно.

## Установка

Необходимо совместно перенести изменения ядра/шаблонов/языковых файлов из `base-active-court` и два файла CDN:
`active-court/main/assets/site/js/common.js`, `active-court/main/assets/common/js/all_device.js`.
После установки обновить кэш этих JS-ресурсов и повторить PoC и обычную форму подтверждения на целевой площадке.
Миграции БД не требуются. Строгую CSP можно рассмотреть отдельно после инвентаризации существующих inline-скриптов.

Подробный контракт: [Service Locator](../../technical/service-locator.md).
