# Имена и выбранная дата бронирования

Дата: 2026-09-11. Ветка `core`, исходный HEAD `4b8017f7`.
Изменения выполнены в рабочем дереве приложения и соседнем репозитории тестов. Ветки и коммиты не изменялись.

## Исправления

### Повторное кодирование имён

Гостевой вход уже сохраняет имена через `StringHelper::shield()`, а регистрация может сохранять экранированные значения.
Повторный `htmlspecialchars()` в новых шаблонах добавлял слой кодирования. Даже `double_encode=false` в шапке и форме
не сохранял `&apos;`, поскольку использовались флаги HTML 4.01.

В `shield()` добавлен четвёртый параметр `bool $doubleEncode = true`.
Существующие параметры, стандартное поведение и обрезка пробелов сохранены.
Вывод имён переведён на `shield(..., doubleEncode: false)` с существующими флагами HTML5:

- шапка и поля общей формы входа;
- основной игрок и варианты выбора дополнительных игроков для site и touch;
- имена расписания в `ReservationsVisualizationCommon` и второй игрок в шаблонах site/touch.

Имена с апострофами и амперсандами отображаются текстом; HTML-ввод продолжает экранироваться.
Повторная отправка гостевой формы не добавляет новый слой кодирования.

### Дата и разрешённые дни

Обнаружены два риска в прежнем порядке обработки:

1. Дата проверялась до загрузки выбранной площадки. При отсутствии `sport_id` использовался минимальный спорт типа,
   который может иметь более короткий период бронирования, чем спорт выбранной площадки.
2. Недоступная дата молча заменялась сегодняшней и затем использовалась моделью оформления.

Выбранная площадка теперь загружается раньше. Её тип и спорт используются как значения по умолчанию,
а явно переданные параметры сохраняют приоритет. Выбор контроллера согласован с этим порядком.
Перед проверкой даты устанавливается предел для текущих типа и спорта.

Недоступная дата отклоняется; заказ не переносится на сегодня. После уточнения задачи обычное открытие страницы
возвращает HTML-страницу 404 с HTTP 404; AJAX и программные запросы сохраняют текстовый HTTP 400.
Нормализация сохраняет сам календарный день и меняет только формат на `Y-m-d`.
Административное исключение, работа с датой ранее загруженной брони и границы стандартного и дополнительного периодов сохранены.

## Уточнение: страница 404

По запросу пользователя обработчик `RequestValidationException` в `App::run()` теперь выводит существующий
шаблон 404 для запросов с `Accept: text/html`, кроме AJAX. Статус ответа — 404, перенаправления нет.
AJAX и запросы без HTML в `Accept` сохраняют прежний ответ 400; контракт валидатора не изменён.
В шаблон передаётся только локализованный текст без пользовательского ввода или сведений исключения.

Заголовок и текст экранируются. Добавлен viewport и проверено размещение блока на мобильных экранах.
В языковых файлах DE/EN/RU секция `http_error` перенесена после секции `exception`: ранее она ошибочно
захватывала последующие ключи, включая `page_not_found`, и мешала получать перевод заголовка.

На `tennisbuchung-test.loc` выполнены 11 дополнительных проверок в установленном Chrome headless:

- исходный XSS PoC на DE/EN/RU: локализованная страница и HTTP 404, ввода в DOM нет;
- массив `date[]` и недоступная дата: HTTP 404;
- ширины 320, 768, 1440 px: нет горизонтального скролла и переполнения текста;
- AJAX и запрос с `Accept: application/json`: прежний текстовый HTTP 400;
- допустимая дата: календарь открывается с HTTP 200.

JavaScript-диалогов и исключений нет. Скриншоты мобильной и настольной версии просмотрены.
PHP-синтаксис изменённых файлов проверен. Временный сценарий, скриншоты и профиль Chrome удалены.
