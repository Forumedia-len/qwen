# Подсистема работы с базой данных

## Обзор

Каталог `core/system/db/` содержит два разных набора компонентов:

- рабочий доступ приложения к MySQL через `Query` и `Dbo`;
- чтение, сравнение и синхронизацию структуры и данных через `DB`, `StructureDB`, `CompareDB`, `CompareDataDB` и `GenerateQueryDB`.

Все классы находятся в пространстве имён `AC\core\system\db`. Они используют конфигурацию `AC\app\config\DBConfig`, а физические имена таблиц формируют с учётом имени базы и префикса таблиц.

Основные связи между компонентами:

```text
Прикладной код
    └── Query ──> Dbo ──> PDO ──> MySQL

Сравнение и миграции
    ├── DB ──> StructureDB ──> Dbo
    ├── CompareDB(DB назначения, DB-эталон)
    ├── CompareDataDB(DB назначения, DB-эталон)
    └── GenerateQueryDB(DB назначения) ──> SQL для последующего выполнения
```

## Краткая справка

| Класс | Для чего нужен | Типичное применение |
|-------|----------------|---------------------|
| `Dbo` | Низкоуровневое PDO-подключение, выполнение подготовленных запросов и чтение метаданных MySQL | Внутри `Query`, `DB` и миграционных классов |
| `Query` | Основная точка выполнения SQL в прикладном коде | Запросы движков, моделей и сервисов |
| `DB` | Подключение по алиасу с загруженной структурой и данными таблиц | Сравнение `site` с `base`, создание и проверка БД |
| `StructureDB` | Преобразование метаданных MySQL в объектное описание схемы | Инициализация `DB` перед сравнением структуры |
| `DataDB` | Минимальная обёртка для чтения всех строк таблицы | Внутренняя загрузка данных классом `DB` |
| `CompareDB` | Поиск отличий структуры целевой БД от эталона | Подготовка структурной миграции |
| `CompareDataDB` | Поиск строк, отсутствующих в целевой справочной таблице | Дополнение справочников данными из эталона |
| `GenerateQueryDB` | Преобразование результата сравнения в SQL | Генерация `CREATE`, `ALTER`, `INSERT`, `UPDATE`, `TRUNCATE` |
| `SyncTwoDB` | Исторический конфигурационный оркестратор синхронизации двух БД | Старые сценарии копирования структуры и данных |
| `QueryBilder` | Небольшой помощник для квалификации полей алиасами таблиц | Сборка списка `c.field`, `cd.field AS name` |

## `Dbo`

Файл: `core/system/db/Dbo.php`.

`Dbo` — самый нижний уровень собственной DB-абстракции проекта. Класс создаёт соединение `PDO`, включает исключения, ассоциативный режим выборки и настоящие подготовленные запросы (`PDO::ATTR_EMULATE_PREPARES = false`). Обычно прикладной код не создаёт `Dbo` напрямую, а получает его через `Query` или `DB`.

Основные обязанности:

- открыть подключение по конфигурации `DBConfig`;
- подготовить и выполнить SQL с плейсхолдерами;
- вернуть все строки в выбранном режиме PDO, в том числе `FETCH_ASSOC`, `FETCH_CLASS`, `FETCH_COLUMN` и `FETCH_FUNC`;
- вернуть одну строку при опции `onlyOne`;
- получить `lastInsertId()`;
- начать, подтвердить или откатить транзакцию;
- сформировать полное экранированное имя таблицы с именем БД и префиксом;
- прочитать таблицы, колонки, первичные/внешние ключи и индексы из `information_schema` и команд MySQL;
- проверить существование таблицы или поля;
- получить `SHOW CREATE TABLE` и все строки таблицы.

`Dbo::getInstance()` поддерживает общий экземпляр, принудительное пересоздание и отдельное подключение через аргумент `$single`. `DB` использует отдельный экземпляр для каждого алиаса, чтобы подключения `site` и `base` не подменяли друг друга.

При ошибке `query()` записывает SQL-ошибку через существующий механизм `Debug()::log(..., 'db')` и возвращает `false`. Поэтому вызывающий код должен отличать ошибку от пустого результата.

## `Query`

Файл: `core/system/db/Query.php`.

`Query` — прикладной фасад над `Dbo`. Это основной класс для обычных запросов из движков, моделей и сервисов. Он доступен напрямую и через `Service::query()`.

Основные обязанности:

- выполнить SQL через `Query::sqlQuery()`;
- выполнить отдельный запрос через подключение с расширенными правами методом `sqlQueryWithExtendedPrivileges()`;
- добавить имя БД и префикс к таблице через `Query::tableName()`;
- хранить ID последней вставленной строки в `Query::getLastId()`;
- переключить текущую БД и префикс через `setBD()`;
- управлять транзакцией статическими методами `beginTransaction()`, `commit()` и `rollBack()`;
- собирать простые условия и плейсхолдеры вспомогательными методами;
- замерять время SQL для режима `debugSql`.

Пример безопасного запроса:

```php
$client = Query::sqlQuery(
  'SELECT * FROM ' . Query::tableName('clients') . ' WHERE client_id = :client_id',
  [':client_id' => $clientId],
  true,
  ['onlyOne' => true]
);
```

Третий аргумент `sqlQuery()` определяет, нужно ли получать строки: `true` возвращает выборку, `false` — результат выполнения команды. `Query` принимает готовый SQL и не является fluent query builder: у него нет цепочки `select()->where()->get()`.

## `DB`

Файл: `core/system/db/DB.php`.

`DB` — высокоуровневая обёртка над отдельным `Dbo`, которая знает структуру выбранной базы. Экземпляры кэшируются по алиасу. Стандартные алиасы из `DBConfig`: `site`, `base`, `old` и `test`; неизвестный алиас получает настройки `site`, если их не переопределить третьим аргументом `DB::instance()`.

```php
$site = DB::instance('site');
$base = DB::instance('base');
```

Класс нужен для задач, где одного выполнения SQL недостаточно:

- получить структуру всей БД, отдельной таблицы или колонки;
- получить список полей и первичных ключей;
- загрузить и закэшировать все строки таблицы;
- сформировать полное имя таблицы;
- выполнить один запрос или массив SQL-команд;
- создать или проверить существование базы, выдать права;
- передать `Dbo` специализированным классам;
- повторно загрузить структуру через `instanceStructure()`.

При создании `DB` загружает структуру через `StructureDB`. Затем `convertCharset()` автоматически переводит таблицы с другой collation в `utf8mb4_unicode_ci` и перечитывает структуру. Поэтому создание нового экземпляра `DB` имеет потенциальный побочный эффект изменения схемы и требует соответствующих прав MySQL.

Данные `getFullDataInTable()` кэшируются внутри экземпляра. После внешнего изменения таблицы этот кэш автоматически не сбрасывается.

## `StructureDB`

Файл: `core/system/db/StructureDB.php`.

`StructureDB` читает метаданные базы через `Dbo` и преобразует их в единый массив объектов, который используют `DB` и `CompareDB`. Ключ массива — логическое имя таблицы без префикса.

Для каждой таблицы сохраняются:

- имя, движок, `AUTO_INCREMENT`, параметры создания, комментарий и collation;
- колонки с типом, `DEFAULT`, nullable-флагом, `EXTRA`, ключом, комментарием и позицией;
- одиночный `primaryKey`, определяемый по колонке `auto_increment`.

Если до создания `DB` определена константа `USE_FULL_STRUCTURE` со значением `true`, дополнительно загружаются все индексы, составной `primaryKeys` и внешние ключи. Полный режим включён в `mapi/act.php` и нужен для корректного сравнения ключей и вторичных индексов.

`StructureDB` только читает и нормализует схему; SQL для её изменения генерирует `GenerateQueryDB`.

## `DataDB`

Файл: `core/system/db/DataDB.php`.

`DataDB` — тонкая статическая обёртка над `Dbo::getAllDataFromTable()`. Метод `getAllData()` возвращает все строки указанной таблицы. Сейчас класс используется только из `DB::getFullDataInTable()` и отделяет получение данных от объекта, который хранит структуру и кэш.

Класс не фильтрует строки, не выполняет постраничную загрузку и не строит запросы. Для выборок с условиями следует использовать `Query`.

## `CompareDB`

Файл: `core/system/db/CompareDB.php`.

`CompareDB` сравнивает две уже загруженные структуры и возвращает описание отличий, но сам ничего не изменяет. Направление аргументов принципиально:

```php
$diff = CompareDB::compareTwoDB($site, $base);
```

Первый `DB` — назначение, которое нужно привести к нужному состоянию. Второй `DB` — эталон.

Класс обнаруживает:

- отсутствующие в назначении таблицы;
- различия движка, комментария и collation таблицы;
- отсутствующие, переименованные и отличающиеся колонки;
- различия первичного ключа;
- отсутствующие вторичные и составные индексы при полной структуре;
- лишние колонки, только если это явно разрешено опцией `dropColumn`.

Опция `replaceColumn` задаёт соответствие нового имени колонки старым вариантам и позволяет получить `CHANGE`, а не создание второй колонки. Лишние таблицы класс не помечает на удаление.

`compareTwoTablesOld()` оставлен как прежняя версия алгоритма. Для нового кода следует применять `compareTwoTables()`. Публичный метод `replaceColumn()` не участвует в текущем алгоритме; фактическая обработка этой опции находится внутри `compareTwoTables()`.

Результат `CompareDB` предназначен для передачи в `GenerateQueryDB`.

## `CompareDataDB`

Файл: `core/system/db/CompareDataDB.php`.

`CompareDataDB` сравнивает содержимое одной таблицы в целевой и эталонной БД по первичному ключу. Он формирует данные для вставки строк, которые есть в эталоне, но отсутствуют в назначении.

```php
$missing = CompareDataDB::compareTableSetBase('config_text', $site, $base);
```

Для составного первичного ключа значения объединяются в технический ключ через `|`. Используются только первичные поля, присутствующие в обеих схемах.

Ограничения класса:

- он не сравнивает значения уже существующих строк;
- не генерирует `UPDATE` или `DELETE`;
- не удаляет строки, которых нет в эталоне;
- при отсутствии подходящего primary key сравнение фактически опирается на исходные ключи массива и не является надёжной синхронизацией произвольных данных.

Поэтому класс предназначен прежде всего для дополнения справочных таблиц с устойчивым первичным ключом.

## `GenerateQueryDB`

Файл: `core/system/db/GenerateQueryDB.php`.

`GenerateQueryDB` превращает описание отличий из `CompareDB` в SQL для целевой базы. Конструктор получает именно тот `DB`, структуру которого планируется менять.

При генерации определений колонок SQL-имена типов приводятся к верхнему регистру. Для `ENUM` и `SET` регистр меняется только у имени типа, а значения внутри списка сохраняются в точности как в эталонной структуре. Это предотвращает изменение строковых значений и повторное появление одного и того же структурного diff.

Поддерживаемые операции:

- `CREATE TABLE` для отсутствующей таблицы;
- `ALTER TABLE` для параметров таблицы;
- добавление, изменение и разрешённое удаление колонок;
- перестроение первичного ключа;
- добавление обычных, уникальных, составных, префиксных, `FULLTEXT` и `SPATIAL` индексов;
- генерация `INSERT`, `UPDATE` и `TRUNCATE` для миграционных сценариев.

Типичный поток:

```php
$diff = CompareDB::compareTwoDB($site, $base, $config);
$generator = new GenerateQueryDB($site);

foreach ($diff as $tableName => $tableDiff) {
  $sql[] = $generator->renderCompareOnTableName($tableName, $tableDiff);
}
```

Класс только возвращает SQL-строки. Просмотр и выполнение делает вызывающий код, например `mapi/act.php` или `DB::executingAllQuery()`.

Генераторы данных собирают SQL строковой конкатенацией и рассчитаны на внутренние, доверенные результаты сравнения и миграционные конфиги. Их нельзя использовать для прямой подстановки пользовательского ввода; для прикладных запросов нужны `Query::sqlQuery()` и плейсхолдеры.

## `SyncTwoDB`

Файл: `core/system/db/SyncTwoDB.php`.

`SyncTwoDB` — старый оркестратор, объединяющий `DB`, `CompareDB` и `GenerateQueryDB` для алиасов `site` и `base`. Он может:

- получить структурный diff;
- сгенерировать SQL синхронизации структуры;
- при создании таблиц скопировать данные из эталона;
- по конфигу сформировать вставку, замену, обновление, дополнение и копирование данных;
- выполнить собранные запросы на выбранном подключении.

В активном коде проекта экземпляр `SyncTwoDB` сейчас не создаётся; в `mapi/act/sync_cort.php` осталась только закомментированная инициализация. Актуальный сценарий обновления БД реализован в `mapi/act.php` напрямую через `CompareDB`, `CompareDataDB` и `GenerateQueryDB`.

Новый код не следует строить поверх `SyncTwoDB` без отдельного решения о восстановлении этого сценария: методы генерации данных используют ручное заключение значений в кавычки и рассчитаны на доверенные миграционные конфиги.

## `QueryBilder`

Файл: `core/system/db/QueryBilder.php`.

`QueryBilder` — небольшой помощник для формирования квалифицированных имён полей при ручной сборке SQL с `JOIN`. Имя класса содержит историческую опечатку (`Bilder`), которую нельзя исправлять без обновления существующих импортов.

```php
$builder = (new QueryBilder())->setTableAlias([
  'clients' => 'c',
  'client_data' => 'cd',
]);

$fields = $builder->fieldNamesWithTableAlias([
  'clients' => ['client_id', ['name', 'clientName']],
  'client_data' => ['value'],
]);
// c.client_id, c.name as clientName, cd.value
```

Класс хранит соответствие «таблица → алиас» и добавляет его к одному полю или массиву полей. Метод `select()` пустой, а методов `where`, `join`, `insert` и выполнения SQL нет. Следовательно, это не полноценный построитель запросов, а форматтер списка полей. Сейчас он используется в `MembershipFeesClientEngine`.

## Как выбрать нужный класс

- Для обычного `SELECT`, `INSERT`, `UPDATE` или `DELETE` используйте `Query` с плейсхолдерами.
- Для транзакции используйте транзакционные методы `Query` или полученного `Dbo`.
- Для проверки таблиц, колонок или чтения метаданных используйте `Dbo`.
- Для работы с полной схемой конкретного подключения используйте `DB`.
- Для сравнения сайта с эталоном используйте `CompareDB`, затем `GenerateQueryDB`.
- Для добавления отсутствующих строк справочника используйте `CompareDataDB`.
- `DataDB` и `StructureDB` являются внутренними поставщиками данных для `DB`.
- `QueryBilder` применяйте только как помощник имён полей.
- Для новых сценариев синхронизации не используйте `SyncTwoDB`; ориентируйтесь на текущий механизм `mapi/act.php`.

Подробный рабочий процесс сравнения эталонной и сайтовой БД описан в [стратегии миграции баз данных](../development/database-migration-strategy.md).
